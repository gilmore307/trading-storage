# shared

Trading-wide reusable static files live here when they are not templates.

Use this folder for reviewed cross-project files such as shared vocabularies, lookup tables, examples, or other static assets that multiple repositories may reference. Do not store secrets, generated runtime outputs, caches, or component-owned implementation files here.

Current files:

- `layer_01_02_market_context_etf_universe.csv` — curated ETF universe for market-state and broad Layer 2 sector/crypto context observation. `model_layer` is the authoritative Layer 1 / Layer 2 scope discriminator: `layer_01_market_regime` rows feed Layer 1 market-context construction, while `layer_02_sector_context` rows feed the 11 broad Select Sector SPDR anchors plus the `BKCH` crypto context-anchor exception. `feature_grain` is the intended downstream observation/feature grain; source acquisition downloads canonical 1-minute bars.
- `layer_01_02_market_context_relative_strength_combinations.csv` — curated market-context relative-strength combinations. `model_layer` is the authoritative scope discriminator: `layer_01_market_regime` rows feed Layer 1 broad market/cross-asset evidence; `layer_02_sector_context` rows feed Layer 2 sector-context evidence. Each row defines `numerator_symbol / denominator_symbol`, `combination_type`, feature-grain cues, `feature_bar_grain`, and `interpretation`. Generated feature values do not belong here. Its columns are registered in `trading-manager`.

- `layer_02_target_context_mapping.csv` — reviewed target-to-Layer-2-context and auxiliary proxy mapping. Layer 3+ target-specific studies may use this file to map non-equity targets such as `BTC`, `ETH`, or `SOL` back to Layer 2 context (`BKCH`) while keeping single-asset ETF proxies (`IBIT`, `ETHA`, `FSOL`) out of Layer 1/2 market/sector context. Equity rows may map targets only to accepted broad Layer 2 anchors such as `XLK` or `XLC`; focused industry-chain and theme ETFs such as `AIQ` or `SMH` are outside the current Layer 2 contract. Proxy symbols in this file are target-specific auxiliary evidence references; they do not become market-regime or sector-context universe rows. This file is seed/fallback mapping evidence for ordinary targets; the accepted future weighting standard is dynamic `target_context_profile` evidence from correlation, lead-lag, influence direction, and confidence.
- `equity_total_symbol_pool.csv` — reviewed realtime equity total-symbol pool used by calendar and event-source monitoring. It is built from TradingView top-300 traded-dollar-value and top-300 market-cap screener snapshots plus optional optionable-underlying lists. ETF holdings do not define this pool. Rows whose optionability has not yet been checked must carry `optionable_underlying_status=uncertain_verify_before_use`; historical replay must not read this mutable realtime pool directly.
- `equity_total_symbol_pool.symbols.txt` — machine-readable symbol list derived from `equity_total_symbol_pool.csv` for `trading-data-calendar-maintenance.service`.
- `historical_candidate_universe.csv` — fixed historical replay candidate universe seeded from the current active realtime pool plus BTC, ETH, and SOL. It preserves TradingView's raw sector classification and maps equity rows to the accepted Layer 2 SPDR sector anchors; crypto rows map to `BKCH`. It is stable replay scope, not point-in-time historical market-wide ranking evidence.
- `historical_candidate_universe.symbols.txt` — machine-readable symbol list derived from `historical_candidate_universe.csv` for replay coverage planning.
